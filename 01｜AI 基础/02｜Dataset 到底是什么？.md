# 02｜Dataset 到底是什么？

> **这一篇只解决一个问题：AI 到底拿什么东西学习？**
>
> 答案是：**Dataset（数据集）**。
>
> 但真正要理解的不是“Dataset = 一堆数据”，而是：**什么样的数据才能成为训练模型的数据，以及数据为什么会直接决定模型最后学成什么样。**

---

## 一、先不要想复杂：Dataset 就是模型学习用的数据

我们先看一个最简单的任务：

> 判断一条短信是不是垃圾短信。

假设我们准备了这些数据：

| 短信 | 正确结果 |
|---|---|
| 恭喜您中奖100万元，点击链接领取 | 垃圾短信 |
| 明天上午10点开项目评审会议 | 正常短信 |
| 您的快递已到，请及时取件 | 正常短信 |
| 恭喜中奖，马上领取现金大奖 | 垃圾短信 |

这些数据放在一起，就可以形成一个用于机器学习的数据集：

```text
Dataset
├── 一条短信
├── 一条正确结果
├── 一条短信
├── 一条正确结果
├── ...
└── 大量样本
```

所以最简单的理解：

> **Dataset = 用来训练、验证或测试模型的一组数据样本。**

但这里有一个非常重要的区别：

> **数据集不是模型。**
>
> 数据集提供“学习材料”，模型负责“从学习材料中找到规律”。

---

# 二、一个 Dataset 里面到底有什么？

对于监督学习来说，一个最典型的数据样本包含两部分：

```text
一个样本
│
├── Input
│
└── Label
```

例如：

```text
Input：
“恭喜中奖100万，点击链接领取”

Label：
“垃圾短信”
```

很多样本组合起来：

```text
Dataset
│
├── Sample 1
│   ├── Input
│   └── Label
│
├── Sample 2
│   ├── Input
│   └── Label
│
├── Sample 3
│   ├── Input
│   └── Label
│
└── ...
```

因此可以先建立一个非常重要的认识：

> **Dataset 不是简单的“文件夹”或者“Excel 表”，而是模型学习任务所使用的一组结构化样本。**

文件只是保存数据的方式。

CSV、JSON、数据库、图片目录、音频文件，都只是 Dataset 的不同存储形式。

---

# 三、Dataset、Sample、Input、Label 不要混淆

这是这一阶段最需要建立的基础概念。

| 概念 | 含义 | 例子 |
|---|---|---|
| Dataset | 一组数据样本 | 10万条短信数据 |
| Sample | 一条具体数据 | “恭喜中奖100万” |
| Input | 模型看到的输入 | 一条短信文本 |
| Label | 对应的正确答案 | 垃圾短信 |

关系可以表示成：

```text
Dataset
  │
  ├── Sample 1 → Input + Label
  ├── Sample 2 → Input + Label
  ├── Sample 3 → Input + Label
  └── ...
```

例如：

```text
Dataset
│
├── Sample 1
│   Input  = “恭喜中奖100万”
│   Label  = “垃圾短信”
│
├── Sample 2
│   Input  = “今晚一起吃饭吗？”
│   Label  = “正常短信”
│
└── Sample 3
    Input  = “您的快递已送达”
    Label  = “正常短信”
```

这样就不要再把 Dataset 和单条数据混为一谈。

---

# 四、为什么 AI 需要 Dataset？

因为机器学习的核心就是：

> **让模型从大量数据中发现规律。**

还是用垃圾短信分类。

如果只给模型一条数据：

```text
“恭喜中奖100万” → 垃圾
```

模型几乎没有办法知道：

- “中奖100万”是不是垃圾特征？
- “恭喜中奖”是不是垃圾特征？
- “点击链接”是不是垃圾特征？
- 以后出现“恭喜您获得大奖”是不是也可能是垃圾？

所以需要大量不同的数据：

```text
中奖100万 → 垃圾
中奖50万 → 垃圾
点击链接领取大奖 → 垃圾
恭喜获得现金奖励 → 垃圾

明天开会 → 正常
快递已送达 → 正常
晚上吃饭吗 → 正常
项目测试完成了吗 → 正常
```

模型通过大量样本，逐渐找到输入和结果之间的规律。

因此：

```text
更多合理的数据
        ↓
模型看到更多情况
        ↓
能够学习更多规律
        ↓
面对新数据时更有可能做出正确判断
```

注意这里是“更有可能”，不是“数据越多一定越好”。

这就是 Dataset 真正重要的地方。

---

# 五、数据多，就一定好吗？

**不是。**

这是测试人员理解 AI 时非常重要的一点。

假设我们有10万条训练数据，但全部都是这种形式：

```text
中奖100万 → 垃圾
中奖50万 → 垃圾
中奖200万 → 垃圾
中奖300万 → 垃圾
...
```

模型可能学到一个非常简单的规律：

> 看到“中奖”就判断为垃圾短信。

但是现实中可能存在：

```text
公司活动中奖通知 → 正常
电商平台抽奖通知 → 正常
朋友开玩笑说“你中奖啦” → 正常
```

模型可能因此产生错误。

这说明：

> **Dataset 的价值不只是数量，还取决于数据是否能够覆盖真实问题。**

所以评价一个 Dataset，不能只问：

> “有多少条？”

还要问：

- 数据来自哪里？
- 覆盖哪些情况？
- 是否存在重复？
- 是否存在错误？
- 类别是否严重不平衡？
- 是否包含真实场景中的边界情况？
- 是否与未来使用环境一致？

这些问题后面都会直接影响模型质量。

---

# 六、Dataset 最重要的问题：它代表什么？

这是比“数据有多少”更重要的问题。

假设你要训练一个模型识别游戏里的按钮。

你的 Dataset 全部来自：

```text
1080 × 1920
Android
英文
白天场景
固定UI
```

训练结果可能很好。

但上线以后用户环境变成：

```text
720 × 1600
iPhone
不同语言
深色模式
不同UI版本
网络延迟
弹窗覆盖
```

模型表现可能马上下降。

为什么？

因为：

> **训练 Dataset 只覆盖了原来的数据分布，而真实环境发生了变化。**

所以 Dataset 本质上是在告诉模型：

> “你应该从哪些现实样本中学习？”

如果 Dataset 和真实世界差距很大，模型学到的东西也可能和真实世界不匹配。

这就是后面 `Generalization` 和 `Distribution Shift` 要解决的问题。

现在先记住这一点就够了。

---

# 七、Dataset 不是越“干净”越好

这里容易出现一个误区：

> “训练数据全部清洗得非常干净，模型一定更好。”

不一定。

例如真实用户输入可能包含：

```text
错别字
口语
缩写
乱码
表情符号
不同语言
异常格式
网络抖动导致的数据异常
```

如果训练 Dataset 被处理得过于理想化：

```text
所有文本都标准
所有图片都清晰
所有输入格式都一致
没有任何异常情况
```

模型可能只会处理“标准输入”。

一旦真实用户输入变复杂，就可能出错。

所以数据质量不是：

> **越完美越好。**

而应该是：

> **数据是否真实、准确、覆盖目标场景，并且能够代表模型未来面对的问题。**

这两者完全不同。

---

# 八、Dataset 中可能有哪些问题？

从测试工程师的角度，可以把 Dataset 看成一种“测试输入集合”。

它可能出现很多典型问题。

## 1. 数据错误

例如：

```text
Input：恭喜中奖100万
Label：正常
```

但实际上它应该是：

```text
Label：垃圾
```

这属于数据或标签错误。

---

## 2. 数据重复

例如同一条数据出现1000次：

```text
“恭喜中奖100万” → 垃圾
“恭喜中奖100万” → 垃圾
“恭喜中奖100万” → 垃圾
...
```

表面上 Dataset 有1000条数据，实际上可能只增加了一个有效信息。

---

## 3. 数据分布不平衡

例如：

```text
正常短信：99,000
垃圾短信：1,000
```

如果模型全部预测：

```text
正常
```

准确率甚至可以达到：

```text
99%
```

但这个模型显然没有真正解决垃圾短信识别问题。

这也是为什么后面学习 Evaluation 时，不能只看 Accuracy。

---

## 4. 数据覆盖不足

训练数据没有覆盖真实场景中的重要情况。

例如游戏 UI 识别 Dataset 只有：

```text
正常按钮
正常背景
正常分辨率
```

却没有：

```text
弹窗
遮挡
低清截图
夜间场景
不同语言
不同分辨率
按钮状态变化
```

上线后自然容易出问题。

---

## 5. 数据与真实环境不一致

训练数据来自旧版本：

```text
V1 UI
```

上线后却变成：

```text
V2 UI
```

模型可能出现明显性能下降。

---

# 九、Dataset 和测试数据有什么关系？

这一点对测试工程师非常重要。

传统软件测试中，我们会设计：

```text
正常输入
异常输入
边界输入
非法输入
极端输入
真实用户输入
```

AI 系统中的 Dataset 本质上也在描述：

> **模型需要面对什么样的数据。**

例如一个 OCR 模型：

```text
Dataset
├── 清晰文字
├── 模糊文字
├── 小字体
├── 大字体
├── 中文
├── 英文
├── 数字
├── 特殊符号
├── 旋转文字
├── 遮挡文字
└── 低光环境
```

这和测试设计非常接近。

因此测试工程师理解 Dataset 后，就会发现：

> **AI 测试并不是完全陌生的东西。只是测试对象从“程序逻辑”逐渐变成了“数据 + 模型 + 输出”。**

---

# 十、Dataset、Training Dataset、Validation Dataset、Test Dataset

Dataset 是一个总称。

真正训练机器学习模型时，通常不会把所有数据全部拿去训练。

而是会划分成不同部分：

```text
完整 Dataset
      │
      ├── Training Set
      │      ↓
      │    用来学习
      │
      ├── Validation Set
      │      ↓
      │    用来调整和选择模型
      │
      └── Test Set
             ↓
           用来最终验证
```

先不用记复杂定义，只记住：

| 数据 | 主要用途 |
|---|---|
| Training Set | 让模型学习 |
| Validation Set | 帮助选择/调整模型 |
| Test Set | 检查模型最终表现 |

后面第10篇会专门解释为什么必须这样划分。

现在只需要知道：

> **不是所有 Dataset 都应该拿来训练模型。**

---

# 十一、一个非常重要的问题：测试数据能不能混进训练数据？

**不能随便混。**

假设：

```text
训练数据：
A、B、C、D

测试数据：
E、F、G
```

模型训练时从来没有看到 E、F、G。

最后我们用 E、F、G 测试模型。

这样才能知道：

> 模型面对没有见过的数据，表现怎么样？

但如果把 G 也放进训练集：

```text
训练：A、B、C、D、G

测试：E、F、G
```

模型已经见过 G。

那么最后 G 预测正确，并不能证明模型真的具备泛化能力。

这就是后面会讲的：

> **Data Leakage（数据泄漏）**

以及在 LLM 场景中经常讨论的：

> **Test Contamination（测试污染）**

现在先建立一个最简单的原则：

> **用来测试模型的数据，原则上不能提前被模型用于学习。**

---

# 十二、最小实验：自己构造一个 Dataset

现在不用任何 AI 框架。

我们直接构造一个最简单的数据集。

```python
samples = [
    {
        "input": "恭喜中奖100万，点击领取",
        "label": "垃圾"
    },
    {
        "input": "今晚一起吃饭吗？",
        "label": "正常"
    },
    {
        "input": "您的快递已经送达",
        "label": "正常"
    },
    {
        "input": "点击链接领取现金大奖",
        "label": "垃圾"
    }
]
```

这里：

```text
samples
   ↓
Dataset
```

每一个字典就是一个 Sample：

```text
Sample
├── input
└── label
```

我们甚至可以简单统计一下：

```python
for sample in samples:
    print(sample["input"], "→", sample["label"])
```

输出：

```text
恭喜中奖100万，点击领取 → 垃圾
今晚一起吃饭吗？ → 正常
您的快递已经送达 → 正常
点击链接领取现金大奖 → 垃圾
```

到这里你已经真正创建了一个最小 Dataset。

它不需要 AI 框架，也不需要 GPU。

因为 Dataset 本身并不神秘。

# 十三、故意制造一个 Dataset 问题

现在我们故意加入错误数据：

```python
samples = [
    {
        "input": "恭喜中奖100万，点击领取",
        "label": "垃圾"
    },
    {
        "input": "今晚一起吃饭吗？",
        "label": "正常"
    },
    {
        "input": "点击链接领取现金大奖",
        "label": "正常"
    }
]
```

第三条明显存在问题：

```text
Input：
点击链接领取现金大奖

Label：
正常
```

如果大量类似错误数据进入训练过程，会发生什么？

模型看到：

```text
点击链接领取现金大奖 → 正常
```

它可能就会学习到错误规律。

所以模型最后预测错误，并不一定是：

> “模型太差。”

也可能是：

> **Dataset 本身就告诉模型了错误的信息。**

这就是 AI 测试和传统软件测试一个非常大的区别：

```text
传统程序
代码逻辑 → 主要由工程师明确编写

机器学习
数据 + 学习算法 → 共同决定模型行为
```

因此：

> **数据质量本身就是 AI 系统质量的一部分。**

---

# 十四、从测试工程师角度重新理解 Dataset

以后看到一个 AI 系统，不要第一反应只问：

> “模型是什么？”

先问：

```text
它用什么数据训练？
        ↓
这些数据从哪里来？
        ↓
数据是否正确？
        ↓
数据覆盖了什么情况？
        ↓
哪些情况没有覆盖？
        ↓
训练数据和真实数据是否一致？
```

这套思维非常重要。

因为很多 AI 问题表面上是：

```text
模型预测错误
```

但真正原因可能在：

```text
Dataset
  ↓
数据质量问题
  ↓
训练数据没有覆盖真实场景
  ↓
模型学到错误规律
  ↓
最终预测错误
```

所以 AI 系统排查不能只盯着模型。

---

# 十五、这一篇最重要的几个结论

如果这一篇只记住下面 8 句话，就够了：

### 1. Dataset 是什么？

> **Dataset 是模型学习、验证或测试所使用的一组数据样本。**

### 2. Dataset 和 Sample 的区别？

> Dataset 是一组样本，Sample 是其中的一条数据。

### 3. Sample 通常包含什么？

监督学习中通常是：

```text
Input + Label
```

### 4. Dataset 为什么重要？

因为模型从 Dataset 中学习规律。

### 5. 数据越多越好吗？

> **不一定。数据的质量、覆盖范围、分布和真实性同样重要。**

### 6. 数据错误会怎么样？

模型可能从错误数据中学习错误规律。

### 7. 为什么 Dataset 要考虑真实场景？

因为训练数据和真实数据差异过大时，模型在真实环境中的表现可能下降。

### 8. 测试数据为什么不能随便进入训练集？

因为模型提前看过测试数据后，测试结果就不能可靠地反映模型面对未知数据的能力。

---

# 十六、把 Dataset 放回整个 AI 链路

现在回到第一阶段最重要的主线：

```text
Dataset
 ↓
Input + Label
 ↓
Model
 ↓
Prediction
 ↓
Error / Loss
 ↓
Parameter Update
 ↓
Training
```

这一篇解决的是第一步：

```text
Dataset
```

下一篇继续解决：

```text
Label / Ground Truth
```

也就是一个非常关键的问题：

> **模型到底怎么知道自己的答案是对还是错？**

例如：

```text
Input：
“恭喜中奖100万”

Model Prediction：
正常

但正确答案是什么？

垃圾
```

这个“正确答案”到底从哪里来？

这就是下一篇要解决的问题。

8. 为什么测试数据不能提前进入训练过程？

如果这些问题都能解释清楚，说明 **Dataset 这个概念已经真正建立起来了**。
